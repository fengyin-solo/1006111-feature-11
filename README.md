# 盾构隧道掘进施工管理平台

面向盾构机台账、掘进环次、管片拼装、同步注浆、渣土外运、地表沉降监测与轴线纠偏的一体化盾构隧道施工管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `shield-tunnel-construction:entries` 这一项，或调用 `resetModule(模块)`。

## 建筑监测 × 地表沉降：权属与报警口径

责任单位交接后，为避免新老单位各维护一份，`building`（建筑监测）与 `settlement`（地表沉降）
执行以下口径，规则集中在 `frontend/src/data/monitoring.ts`，页面不做业务判断：

- **按权属划开**：每条监测对象唯一归属一个「当前权属单位」。`对象编号`、`允许沉降` 只允许权属
  单位维护；跨单位改动、监理改动一律拒收，报错注明该记录归属单位。监理身份拿到的是只读共享副本，
  页面不给修改入口，服务层也再拦一道。
- **存量回填**：以交接基准日 `2026-06-01` 划断，按`布点时间`回填权属——早于该日归老单位
  （中铁城建设备管理部），当日及以后归新单位（宏晟盾构监测中心）。老数据缺布点时间时按对象编号
  确定性补（尾号奇数落交接前、偶数落交接后），反复迁移结果一致。允许沉降/实测沉降是占位文字的
  老数据原样保留并标「待复核」，不编造控制值、不静默抹掉历史报警。
- **越限自动报警、两处同源**：提交实测后按 `实测沉降 > 允许沉降`（统一毫米）自动判定，依据
  GB 50911-2013 及产权方控制值；报警提示带测点位置、超限幅度与判定标准。报警结论统一落到
  地表沉降清单（行内 `报警来源=building` 标记），建筑监测页与地表沉降页的报警点数都读
  `listAlarms()` 这一个函数，两边说法不一时以报警台账为准自动对账修正。解除报警两边同步撤回。
- **监测频次**：只有本单位监测负责人可调整，直接覆盖、只保留最后一次生效的值。
- **幂等与事务**：实测提交按对象 upsert（反复提交只入一条）；登记按对象编号去重；建筑监测与
  报警台账一次性原子提交，写失败整条抽回。
- 页面右上角可切换身份（新/老单位的监测负责人、监测员，监理只读）验证上述权限。

本地校验：

```bash
cd frontend
npm run verify:domain   # 回填、对账、同源、判据的纯领域校验
npm run verify:service  # 权属拒收、频次权限、幂等、事务的服务层校验
```
